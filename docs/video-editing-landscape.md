# 移动视频剪辑技术全景图

> **文档版本**：v1.0  
> **更新日期**：2026-05-29  
> **适用项目**：yijian（一剪）视频剪辑 App  

---

## 概述

移动视频剪辑是一条完整的数据处理管线，从媒体读取到最终导出，每个环节都有对应的技术选型。本文档从全局视角梳理业界主流方案，为 yijian 项目技术选型提供参考。

## 主流方案全景

### 1. 原生平台方案（推荐）

| 平台 | 方案 | 层次 | 特点 |
|------|------|------|------|
| Android | **Media3 Transformer** | 高层 API | Google 官方，MediaCodec 硬件加速，OpenGL 特效 |
| Android | **MediaCodec + MediaMuxer** | 低层 API | 最大灵活性，最高性能，复杂度高 |
| Android | **LiTr** | 中间层 | LinkedIn 开源，BSD 协议，可扩展架构 |
| iOS | **AVFoundation** | 高层 API | Apple 官方，AVMutableComposition 多轨编辑 |
| iOS | **VideoToolbox** | 低层 API | 硬件编解码，最低延迟，精细控制 |
| iOS/macOS | **Core Image + Metal** | 渲染层 | 200+ 内置滤镜，GPU 加速，实时渲染 |

### 2. 跨平台方案

| 方案 | 状态 | 适用场景 |
|------|------|---------|
| **FFmpegKit** | ⚠️ 已停止维护（2025年归档） | 复杂转码、格式转换，需用社区 Fork |
| **OpenCV** | ✅ 活跃 | 图像处理、CV 相关特效 |
| **GStreamer** | ✅ 活跃 | 流媒体，移动端支持有限 |
| **原生 KMP 桥接** | ✅ 推荐 | expect/actual 模式，最优移动性能 |

### 3. 商业 SDK

| SDK | 厂商 | 特点 | 费用模式 |
|-----|------|------|---------|
| **Banuba SDK** | Banuba | AR 特效、美颜、面部追踪 | 商业授权 |
| **Videoleap SDK** | Lightricks | 滤镜、特效 | 授权费 |
| **ByteDance 效果 SDK** | 字节跳动 | 剪映同款特效引擎 | 商业合作 |
| **NVSDK** | Nvidia | 超分、降噪（桌面端为主）| 商业授权 |

### 4. 行业标杆技术栈

#### 剪映 / CapCut（字节跳动）
- **编解码**：Android MediaCodec / iOS VideoToolbox（硬件加速）
- **特效渲染**：自研 GPU 渲染引擎（基于 OpenGL ES / Metal）
- **LUT 滤镜**：自定义着色器 + 预生成 LUT 纹理
- **文字**：自研字体渲染引擎
- **AI 特效**：TensorFlow Lite / Core ML 本地推理
- **跨平台**：Android + iOS + Web（各平台独立实现，UI 共享部分组件）

#### 剪辑宝 / InShot
- 偏向 FFmpeg 命令行方案（低开发成本，转码性能弱于原生）


### 关键性能指标（参考）

| 操作 | 目标性能 | 影响因素 |
|------|---------|---------|
| 1080p 视频裁剪（无重编码） | < 1s | I/O 速度 |
| 1080p 30s 滤镜导出 | 10-30s | 硬件加速、滤镜复杂度 |
| 4K 30s 导出 | 30-90s | 编码器性能 |
| 实时预览帧率 | ≥ 30fps | GPU 渲染效率 |
| 缩略图生成（10帧） | < 500ms | 解码速度 |

## 技术选型核心原则

1. **优先使用平台原生 API**：最优性能、最低功耗、最好系统兼容性
2. **硬件加速优先**：MediaCodec/VideoToolbox 硬件编解码比软件快 5-10x
3. **GPU 渲染特效**：OpenGL ES / Metal 实时滤镜，避免 CPU 处理
4. **KMP expect/actual 模式**：视频处理逻辑各平台独立实现，UI 层 KuiklyUI 共享
5. **避免 FFmpeg 重编码**：裁剪/分割尽量用容器层操作，无损且极快
